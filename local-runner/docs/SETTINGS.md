# Local Runner の設定

Local Runner の設定は、`competitive-programming-tools` フォルダの `local-runner.settings.json` の1つにまとめています。Windows の CLI と WSL のサーバーが同じファイルを読みます。

- 書くのは変えたい項目だけです。書かなかった項目は既定値で動きます。
- ファイルが無ければ、すべて既定値で動きます。`setlib` と `setheader` は、このファイルを作って書き込みます。
- 環境ごとに違うので、Git には入れません。
- 既定値の一覧は [src/settings/defaults.json](../src/settings/defaults.json) です。このファイルは書き換えず、同じ形で `local-runner.settings.json` に書きます。

## 設定の移行

`settingsVersion` が `1` の設定は、起動時に形式 `2` に移行します。形式番号がない場合は、`librarySourceRoot`、`headerFiles`、言語ごとの `debugRewrite` のいずれかがあるときだけ移行します。`librarySourceRoot` は `languages.java.library` に、`headerFiles` の各項目は `headers` に移し、同じ項目に新しい設定があればそちらを使います。`debugFlag` が未設定なら、`debugRewrite: true` の言語にだけ `debugFlag: "DEBUG"` を設定します。

移行後の設定を一時ファイルで検証し、元の内容を同じフォルダの `.bak` に保存してから設定ファイルを置き換えます。**検証に失敗すると起動はエラーで終了し、元の設定ファイルが残ります。**

## 書き方

Java のライブラリとヘッダーを設定し、ポートを変える例です。

```json
{
	"$schema": "./local-runner/settings.schema.json",
	"server": {
		"port": 8081
	},
	"languages": {
		"java": {
			"library": "C:/Users/me/cp/my-library/src"
		}
	},
	"headers": {
		"java": "C:/Users/me/cp/header.txt"
	}
}
```

`$schema` を書いておくと、VS Code や JetBrains の IDE が項目の補完と説明、既定値を表示します。

## 項目

「反映」の列は、変更が効く時期です。「再起動」は `stop` のあと `serve` が要る項目、「すぐ」は次のコマンドから効く項目です。

### server

| 項目             | 既定値  | 反映   | 説明                                                                                              |
|------------------|---------|--------|---------------------------------------------------------------------------------------------------|
| `port`           | `8080`  | 再起動 | サーバーのポート。CLI の接続先もここから決まります。                                              |
| `backend`        | `"wsl"` | すぐ   | Windows でサーバーを動かす場所。`"native"` にすると、WSL を使わずに Windows の JDK で動かします。 |
| `autoStart`      | `true`  | すぐ   | サーバーが動いていないとき、`test` などのコマンドが自動で起動します。                             |
| `startTimeoutMs` | `60000` | すぐ   | 自動で起動したサーバーの準備を待つ時間(ms)                                                        |
| `extraOrigins`   | `[]`    | 再起動 | 対応するジャッジサイトのほかに、ブラウザからの要求を許すオリジン                                  |

ポートを変えたら、CP Toolkit の設定にある Local Runner の URL も同じポートに変えてください。

`extraOrigins` に書いたオリジンのページは、この PC でコードを実行できるようになります。自分で用意したページだけを書いてください。

`backend` を `"native"` にすると、WSL を使わずに Windows でサーバーを動かします。Windows の JDK 24 以降が要り、動くのは Java だけです。

### run

| 項目               | 既定値  | 反映   | 説明                                                       |
|--------------------|---------|--------|------------------------------------------------------------|
| `timeoutMs`        | `10000` | 再起動 | 1回の実行を打ち切る時間(ms)                                |
| `compileTimeoutMs` | `30000` | 再起動 | コンパイルと提出用の変換を打ち切る時間(ms)                 |
| `outputLimitMb`    | `2`     | 再起動 | 標準出力と標準エラー出力のそれぞれで、取り込む量の上限(MB) |
| `maxParallelRuns`  | `8`     | 再起動 | サーバー全体で同時に動かすコマンド言語の実行数の上限       |

たとえば `"run": {"maxParallelRuns": 16}` とすると、サーバーに利用可能な論理 CPU が16個なら最大16ケース、6個なら最大6ケースを実行します。実際の枠数は `status` で確認できます。枠が空くと次の要求を開始し、使わない枠にプロセスを常駐させることはありません。メモリ消費が大きい解答や制限時間に近い解答を単独で測るときは `1` にできます。通常の Java 実行とコンパイルにはそれぞれ独立した順番待ちがあります。

### languages

言語ごとの実行環境です。名前(`java`、`cpp` など)ごとに項目を書きます。反映は「再起動」です。`submit` だけは CLI が読むので「すぐ」です。

既定では次の10個の定義が入っています。入っているのは定義だけで、Java 以外の処理系は自分で入れる必要があります。処理系が見つからない言語は使わないだけで、サーバーは起動します。使える言語は `status` で確かめられます。

| 名前      | 種類      | 既定の `command` | 内容                                                                                        |
|-----------|-----------|------------------|---------------------------------------------------------------------------------------------|
| `java`    | `java`    | `java`           | 常駐する JVM で動かします。`lib.*` の展開と `Main` への変換を行います。                     |
| `cpp`     | `cpp`     | `g++`            | C++23、GCC 15、`-Og -pipe`。標準ヘッダーを起動時に準備します。                              |
| `c`       | `c`       | `gcc`            | C23、`-O2 -pipe`。                                                                          |
| `cpython` | `python3` | `python3`        | 組み込みの `compile()` で実行前に構文を検査します。                                         |
| `pypy`    | `python3` | `pypy3`          | 同上                                                                                        |
| `codon`   | `python3` | `codon`          | `codon build --release` でコンパイルします。                                                |
| `go`      | `go`      | `go`             | よく使う標準パッケージを起動時にビルドし、Go のビルドキャッシュを共有します。               |
| `rust`    | `rust`    | `rustc`          | `rustc -O` で標準ライブラリを使う単一ファイルをコンパイルします。                           |
| `kotlin`  | `kotlin`  | `kotlinc`        | kotlinc の標準配置ではランタイムを共有し、JAR のエントリーポイントを Java で起動します。    |
| `csharp`  | `csharp`  | `dotnet`         | .NET 9 SDK とランタイムを使います。プロジェクトを一度 restore し、解答ごとに build します。 |

- 既定の言語は、変えたい項目だけを書けば残りは既定値のままです。処理系が PATH に無いときは、`command` にパスを書きます。
- C++ の既定はコンパイルを速くする `-Og` です。AtCoder の `-O2` より実行が遅くなることがあります。同じ最適化で測るときは、`languages.cpp.compile` を配列ごと書き換えて `-O2` を指定します。
- 各言語の計測環境と検証範囲は[サーバーの処理と実測](SERVER_ARCHITECTURE.html)にあります。
- AtCoder と違うバージョンの処理系でも動きますが、オプションが合わないときは `compile` を書き換えます。たとえば GCC 14 以前は `-fmodules` を受け付けません。
- Java 以外の言語は、サーバーが WSL か Linux で動いているときだけ使えます。
- Codon は Python と書き方が違うところがあり、CPython 向けのコードがそのまま動くとは限りません。

#### languages.java

| 項目          | 既定値   | 説明                                                                                                            |
|---------------|----------|-----------------------------------------------------------------------------------------------------------------|
| `command`     | `"java"` | `java` の命令。名前だけなら `java` と `javac` を PATH から探します。パスなら同じフォルダの `javac` を使います。 |
| `release`     | `24`     | 提出先の Java のバージョン。JDK の方が新しいときは、javac の `--release` で揃えます。                           |
| `library`     | なし     | Java のライブラリのソースを置いたフォルダ。`setlib` が書き込みます。                                            |
| `libraryLast` | `[]`     | ライブラリを展開するときに、末尾へ回すパッケージ(例: `["lib.io"]`)                                              |
| `debugFlag`   | なし     | デバッグの有無に合わせて値を書き換える変数の名前(例: `"DEBUG"`)。書かなければ書き換えません。                   |
| `stackMb`     | `256`    | 解答を実行するスレッドのスタック(MB)                                                                            |

- `library` 配下の `.java` を再帰的に読みます。名前が `.` で始まるフォルダと、`package-info.java`、`module-info.java` は展開の対象外です。フォルダ名は自由で、各ファイルの `package` 宣言からパッケージを決めます。
- `debugFlag` で書き換えるのは、起動するクラスのフィールドのうち、その名前で初期値が `true` か `false` のものだけです。メソッドの中の変数や、ほかのクラスのフィールドは変えません。
- `libraryLast` に書いたパッケージの型は、下位のパッケージのものも含めて、展開した提出物の末尾に並べます。入出力のように大きくて毎回同じクラスを書くと、解答に固有の部分が先にまとまります。書かなければ、依存の順に並べます。

#### Java 以外の言語

コンパイルと実行をコマンドで行います。

| 項目          | 説明                                                                                                        |
|---------------|-------------------------------------------------------------------------------------------------------------|
| `family`      | 言語の種類(`cpp`、`python3`、`rust` など)。CP Toolkit は、ページの言語と同じ種類の実行環境を候補にします。  |
| `name`        | 表示に使う名前                                                                                              |
| `match`       | ページの言語の表記にこの語が含まれていれば、同じ種類の中でこの実行環境を先頭にします(例: `["PyPy"]`)。      |
| `submit`      | AtCoder の提出フォームの言語名に含まれる文字列(例: `"C++23 (GCC"`)。`submit` がこの言語で提出します(後述)。 |
| `command`     | 処理系の命令。名前だけなら PATH から探します。パスなら、サーバーが動く側(WSL)のパスで書きます。             |
| `sourceFile`  | 作業フォルダへ書き出すソースのファイル名(例: `Main.cpp`)                                                    |
| `compile`     | コンパイルの引数の並び。書かなければコンパイルしません。                                                    |
| `compilePath` | コンパイル時の PATH。`"auto"`（既定）または `"inherit"` を指定します。                                      |
| `run`         | 実行の引数の並び                                                                                            |
| `debugArgs`   | デバッグが有効なとき、`compile` の末尾に足す引数(例: `["-DLOCAL"]`)                                         |
| `debugFlag`   | デバッグの有無に合わせて値を書き換える変数の名前(例: `"DEBUG"`)。書かなければ書き換えません(後述)。         |
| `stackMb`     | スタックの上限(MB)。既定値は `1024`                                                                         |
| `setup`       | 組み込みの準備処理を選びます。`"none"` で無効にできます。                                                   |
| `bundle`      | コンパイルの前と提出物の作成で通す、変換のコマンド(後述)                                                    |
| `enabled`     | `false` にすると、この言語を使いません。                                                                    |

`debugFlag` に対応する `family` と、書き換える宣言は次のとおりです。書き換えるのは、関数やブロックの外に1行で書いた宣言・代入だけです。コメントや文字列の中、関数の中の変数、`true` や `false` だけではない初期化式は変えません。対象が2つ以上あるときと、表にない `family` に `debugFlag` を書いたときは、変換エラーになります。

| `family`   | 書き換える宣言の例                                        |
|------------|-----------------------------------------------------------|
| `python3`  | `名前 = True`、`名前: bool = False`                       |
| `c`、`cpp` | `const bool 名前 = true;`、`constexpr bool 名前 = false;` |
| `go`       | `const 名前 = true`、`var 名前 bool = false`              |
| `rust`     | `const 名前: bool = true;`、`static 名前: bool = false;`  |

`compile`、`run`、`bundle` の引数では、次の名前が置き換わります。先頭が `~/` の引数は、ホームからのパスになります。

| 名前        | 置き換わる内容                     |
|-------------|------------------------------------|
| `{command}` | `command` の実体の場所             |
| `{source}`  | `sourceFile` の名前                |
| `{output}`  | コンパイルで作る実行ファイルの場所 |
| `{dir}`     | そのプログラムの作業フォルダ       |

コンパイルはプログラムごとの作業フォルダで行います。コマンド言語の実行では、その内容をケース専用のフォルダへ複製し、そこをカレントにします。実行時に相対パスで作ったファイルは、そのケースの終了時に削除します。

WSL の C・C++ では、`compile` の先頭が `{command}` で Linux 版の GCC を直接起動するとき、`"auto"` はコンパイルと header unit の生成時に PATH から Windows ドライブ（`/mnt/c` など）のディレクトリを省きます。GCC が補助ツールを探す時間を短くするためです。`command` は先に通常の PATH または設定のパスから解決します。Windows ドライブ上のアセンブラなどを PATH から呼ぶ場合は、その言語に `"compilePath": "inherit"` を設定します。

起動時の任意のコマンドは `warmup` に引数の配列で指定します。例として Go の既定値は `go build bufio fmt sort strconv strings container/heap` です。`[]` で省略できます。失敗の理由はサーバーログに記録します。

Kotlin の `builtin:kotlin-runtime` は、設定がランタイムを含める JAR の生成と `java -jar` の組み合わせで、コンパイラと同じ配布物に必要なライブラリが揃う場合に使います。それ以外は指定したコマンドで動きます。C# の `builtin:dotnet-project` では、`compile` の引数 `{project}` が復元済みの `Main.csproj` の場所になります。別のプロジェクトを使う場合は `compile` と `run` を設定できます。

#### 言語を足す

新しい名前で `family`、`name`、`command`、`sourceFile`、`run` を書くと、言語が増えます。名前は英小文字で始め、英小文字、数字、`-`、`_` を使います。Ruby を足す例です。`compile` では構文だけを検査しています。

```json
{
	"languages": {
		"ruby": {
			"family": "ruby",
			"name": "Ruby",
			"command": "ruby",
			"sourceFile": "Main.rb",
			"compile": ["{command}", "-c", "{source}"],
			"run": ["{command}", "{source}"]
		}
	}
}
```

書き方の例は、既定の言語の定義([src/settings/defaults.json](../src/settings/defaults.json))も参考にしてください。

#### submit の書き方

`submit` で提出するには、`submit` の項目も書きます。AtCoder の提出フォームに並ぶ言語名の一部で、ほかの言語と区別できる長さにします。合う言語がフォームに無いときは、候補を表示して止まります。

- フォームの言語名は `C++23 (GCC 15.2.0)` のように、かっこの中にバージョンが入っています。`"C++23 (GCC"` のようにバージョンの手前で切っておくと、AtCoder がバージョンを上げても一致します。かっこを閉じていないのは、このためです。
- 照合は単純な部分一致で、正規表現ではありません。かっこや `+` をそのまま書けます。大文字と小文字は区別しません。

ソースの拡張子で選べるようにするには、`extensions` に足します。

#### header unit

`#include <bits/stdc++.h>` は標準ライブラリの全体で、コンパイルのたびに読むのに数秒かかります。`"setup": "builtin:gcc-header-unit"` を書くと、読み終えた結果を保存して使い回します。

- 保存先は `~/.cache/competitive-programming/local-runner/header-units` です。1つが約 30MB で、今の設定で使わなくなったものは起動時に消します。
- 標準ライブラリの中身はマクロやオプションで変わるので、コンパイルの引数の組ごとに別のものを作ります。作るのは最初の1回で、5秒ほどかかります。
- ソースの `#include` より前に書いた `#define` と `#pragma GCC optimize` は、標準ライブラリには効きません。効かせたいときは、マクロを `compile` に `-D` で書くか、`"setup": "none"` を指定します。
- g++ と、`compile` の中の `-fmodules` が必要です。作れなかったときは、header unit なしでコンパイルします。

#### bundle

`bundle` には、ソースを標準入力で受け取り、変換したソースを標準出力へ返すコマンドを書きます。自作のライブラリを1つのファイルへ展開するツールなどを組み込めます。

- 実行の前のコンパイルと、提出物の作成(`submit`、`tomain`、`toclip`)の両方で通します。
- 終了コードが 0 以外なら、エラー出力をコンパイルエラーとして表示します。

#### 時間とメモリ

Java 以外の言語は、サンプルごとにプロセスを起動して測ります。

- 時間は、プロセスの起動から終了までです。インタープリターの起動時間も含みます。
- メモリは、プロセスが同時に使った物理メモリの最大値で、処理系の分を含みます。AtCoder の「メモリ」に近い値です。
- Java の値は、実行中に確保したメモリの合計です。解放した分も足されるので、ほかの言語や AtCoder の値とは比べられません。
- 正確に測るために、解答のプロセスを小さな起動プログラムを通して起動します。Release の配布物には、このプログラムが入っています。リポジトリのソースから動かすときは起動時にビルドするので、C コンパイラ(`cc` か `gcc`)が要ります。無いと、約 20MB より小さい値が正しく出ません。

### extensions

ソースの拡張子から言語を選ぶ対応です。値は `languages` の名前で、反映は「すぐ」です。

| 拡張子  | 既定値      |
|---------|-------------|
| `.java` | `"java"`    |
| `.cpp`  | `"cpp"`     |
| `.c`    | `"c"`       |
| `.py`   | `"cpython"` |

- `.py` を PyPy で動かすなら、`".py": "pypy"` と書きます。1回だけ変えるときは、コマンドに `--lang=pypy` を付けます。
- 拡張子を省いた指定(`test d` や `test abc448_d D`)は、ここにある拡張子でソースを探します。

### headers

提出物の先頭に付けるファイルを、名前ごとに書きます。`setheader` が書き込みます。反映は「すぐ」です。

- 名前が言語の名前(`java`、`pypy` など)か種類(`python3` など)なら、その言語の既定のヘッダーになります。両方あれば名前を優先します。
- それ以外の名前は、`--header=<名前>` で選びます。

### atcoder

| 項目           | 既定値                     | 反映 | 説明                                     |
|----------------|----------------------------|------|------------------------------------------|
| `sessionFile`  | `"~/.atcoder/session.txt"` | すぐ | `REVEL_SESSION` の値を保存するファイル   |
| `sampleCache`  | `true`                     | すぐ | 取得したサンプルを保存して使い回します。 |
| `resultWaitMs` | `300000`                   | すぐ | 提出の結果が確定するのを待つ時間(ms)     |

`REVEL_SESSION` の値そのものは、設定ファイルには書きません。`setsession` が `sessionFile` へ保存します。

### update

| 項目         | 既定値                                      | 反映   | 説明                                                                   |
|--------------|---------------------------------------------|--------|------------------------------------------------------------------------|
| `check`      | `true`                                      | 再起動 | サーバーの起動時に、新しいバージョンがあるかを配布元へ問い合わせます。 |
| `repository` | `"nsubaru11/competitive-programming-tools"` | すぐ   | 配布元の GitHub のリポジトリ(`所有者/名前`)                            |

- `check` が `true` のとき、サーバーは起動のたびに GitHub へ1回だけ問い合わせます。新しいバージョンがあれば、起動のログと `status` に表示します。通信できないときは、何も表示せずに続けます。
- `update` は、`repository` の Release のうち、タグが `local-runner-v<バージョン>` のものから最新を選びます。フォークした配布物を使うときは、ここを変えます。

## パスの書き方

設定は Windows の CLI と WSL のサーバーの両方が読むので、パスは読む側に合わせて読み替えます。

| 書き方                 | 読まれ方                                                                              |
|------------------------|---------------------------------------------------------------------------------------|
| 相対パス               | 設定ファイルのあるフォルダから。どちらが読んでも同じ場所を指します。                  |
| `C:/...`、`/mnt/c/...` | 読む側の形に自動で読み替えます。                                                      |
| `~/...`                | 読む側のホーム。WSL のサーバーなら WSL のホーム、Windows の CLI なら Windows のホーム |
| `/home/...`            | WSL だけにある場所。サーバーが読む項目にだけ書けます。                                |

- `competitive-programming-tools` フォルダの中のファイルは、相対パスで書くのを勧めます。
- JSON では `\` を `\\` と書く必要があります。`C:/Users/...` のように `/` で書けます。
- `languages` の `command` と `library`、`headers` はサーバーが読みます。`atcoder.sessionFile` は CLI が読みます。
- `"server.backend": "native"` のときはサーバーも Windows で動くので、`languages.java.command` は Windows のパスで書きます。

## 設定を確かめる

| コマンド   | 表示するもの                                                                       |
|------------|------------------------------------------------------------------------------------|
| `settings` | 全項目と今の値。既定値と違う項目には `*` が付きます。                              |
| `status`   | 設定ファイルの場所。サーバーの起動後に「再起動」の項目が変わっていれば知らせます。 |

設定ファイルに誤りがあると、コマンドは項目の名前と理由を表示して止まります。

- `unknown setting`: 項目の名前が違います。
- `must be an integer` など: 値の型や範囲が違います。
- `is not valid JSON`: かっこやカンマなど、JSON の書き方が違います。
