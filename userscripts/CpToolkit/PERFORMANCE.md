# CP Toolkit の性能

CP Toolkit は、以前は別々の UserScript だった機能を1本にまとめたものです。統合前の UserScript 群と、同じ機能だけを ON にした CP Toolkit を、実際の Tampermonkey で同じ条件で動かして比べました。

## 1. 結果(3.0.2)

AtCoder の9ページを開いたときの、スクリプトなしの状態からの増分の合計です。小さいほど軽いことを表します。

| | 旧スクリプト 25本 | CP Toolkit(同じ機能) | 旧 nsubaru 版 8本 | CP Toolkit(同じ機能) |
|---|---:|---:|---:|---:|
| CPU 時間 | **458 ms** | 540 ms(+18%) | **226 ms** | 495 ms(+119%) |
| メモリ(GC 後の JS ヒープ) | **7.40 MB** | 8.61 MB(+16%) | **3.66 MB** | 7.10 MB(+94%) |
| 複数のスクリプトや機能が触った要素 | 298 | **87**(-71%) | 103 | **53**(-49%) |
| 強制レイアウトの疑い | 7 | **0** | 6 | **0** |

- 旧スクリプトが多く動くページでは、CP Toolkit の方が軽くなります。問題文のページでは CPU 時間が 139 ms から 71 ms に、メモリが 1.66 MB から 0.92 MB に、解説一覧のページでは CPU 時間が 110 ms から 74 ms に減りました。Tampermonkey はスクリプト1本ごとに注入と GM API の準備をするので、本数が減るとその分が減ります。
- 旧スクリプトがほとんど動かないページ(トップ、ユーザー、成績表など)では、CP Toolkit の方が重くなります。機能が動かないページでも、全機能のコードを読み込むためです。9ページの合計では、この分が上回りました。
- DOM への重複アクセスは大きく減りました。旧スクリプトでは、同じ要素を別々のスクリプトがそれぞれ探し直していました。
- 1.0.26 と比べると、同じ機能の CP Toolkit は CPU 時間が 432 ms から 540 ms に、メモリが 7.08 MB から 8.61 MB に増えました。旧スクリプトとの合計の比較は、1.0.26 では CP Toolkit が軽く(-16%)、3.0.2 では重く(+18%)なっています。
- 3.0.2 には「成績表の色付け」の機能がないので、対応する旧スクリプト PerformanceColorizer を比較から外しました。旧スクリプトは 1.0.26 のときより1本少ない25本です。

ページごとの値、機能ごとの内訳、検定の結果は [3.0.2 の詳細](./bench/reports/3.0.2.md) にあります。

## 3. 測り方

- 旧スクリプトは、統合前の nsubaru 版8本の最終版と、[SOURCES.md](./SOURCES.md) で「派生」「模倣」の元になった公開スクリプト18本です。その版に対応する機能がない旧スクリプトは、比較から外します。CP Toolkit は、旧スクリプトに対応する機能だけを ON にしました。
- Tampermonkey を入れた Chromium で、録画した AtCoder の公開ページ9つを開き、CPU プロファイル、GC 後の JS ヒープ、ページ全体の処理時間、放置時の CPU 時間を測りました。
- DOM への重複アクセスだけは、Tampermonkey の代わりの軽いシムで測りました。Tampermonkey のスクリプトはページとは別の実行環境で動き、ページ側から DOM API の呼び出しが見えないためです。
- 提出一覧・順位表・提出画面はログインが要るので対象外です。

手順、計測のコード、再現の方法は [bench/README.md](./bench/README.md) にあります。`bench/setup.sh` と `bench/run.sh` で、どの版でも同じように測れます。
